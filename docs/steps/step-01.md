# Step 1. 데이터 분리 · 가격 숫자화 · 검색 연결 · 빈 상태 화면

> 커밋: `7722df3` · 완료일: 2026-09-22

## 목표
처음 받은 템플릿은 "보이기만 하는 화면"이었다. 데이터가 컴포넌트 안에 박혀 있었고, 검색창은 입력해도 아무 일이 일어나지 않았다.
Step 1의 목표는 이 화면을 **데이터를 받아 움직이는 화면**으로 바꾸는 것이다.

## 한 일

### 1. 데이터 분리 — `src/data/products.js`
- 컴포넌트 안에 있던 상품 배열을 별도 파일로 옮겼다.
- **왜?** 화면(컴포넌트)과 데이터를 나눠 두면 Step 5에서 데이터를 API로 받아올 때 이 파일만 바꾸면 된다.
- 카테고리, 평점, 재고 필드를 추가해 실제 쇼핑몰 데이터에 가깝게 만들었다.

### 2. 가격을 숫자로 — `src/lib/format.js`
- `'₩189,000'` 같은 문자열 대신 `189000` 숫자로 저장하고, 화면에 보여 줄 때만 `formatPrice()`로 바꾼다.
- **왜?** 정렬(Step 2)과 합계 계산(Step 4 장바구니)을 하려면 숫자여야 한다.
- `Intl.NumberFormat`은 브라우저 내장 기능이라 라이브러리가 필요 없다.

### 3. 검색 연결 — `App.jsx`, `SearchBar.jsx`, `CardGrid.jsx`
- 검색어를 `App`의 `useState`로 관리하고, `SearchBar`에는 `value`와 `onChange`를 props로 내려준다.
- 이런 방식을 **제어 컴포넌트**라고 한다. input의 값이 React state와 항상 같다.
- `CardGrid`가 검색어를 받아 상품명·카테고리로 걸러냈다. (Step 2에서 이 역할을 분리함)

### 4. 빈 상태 화면 — `CardGrid.jsx`
- 검색 결과가 0개면 빈 화면 대신 "결과가 없습니다"와 다음 행동을 안내한다.
- 실무에서는 **빈 상태 · 로딩 · 에러** 세 가지 상태를 항상 챙긴다. 포트폴리오에서 이걸 보여 주면 좋다.

### 5. 마크업 · 접근성 (퍼블리셔 강점)
- 카드는 `article`, 목록은 `ul/li`로 바꿨다.
- 장식용 글자는 `aria-hidden`으로 숨기고, 별점은 `sr-only`로 스크린리더용 문장을 따로 넣었다.
- 상품 개수 문구에 `aria-live="polite"`를 달아, 검색 결과가 바뀌면 스크린리더가 알려 준다.

### 기타
- `eslint.config.js`에서 `react/prop-types` 규칙을 껐다. Step 9에서 TypeScript로 타입을 검사할 예정이다.

## 핵심 개념 정리
| 개념 | 한 줄 설명 |
| --- | --- |
| props | 부모가 자식에게 넘겨주는 값. 자식은 읽기만 한다 |
| state (`useState`) | 컴포넌트가 기억하는 값. 바뀌면 화면이 다시 그려진다 |
| 제어 컴포넌트 | input 값을 React state로 관리하는 방식 |
| 조건부 렌더링 | `조건 && <요소>` 또는 `조건 ? A : B`로 상황에 따라 다른 화면을 그린다 |
| `key` | 목록 항목을 구분하는 이름표. index 대신 고유 id를 쓴다 |
